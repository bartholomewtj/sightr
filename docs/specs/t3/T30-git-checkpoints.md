# T30 — Git checkpoints: a snapshot at each run's start and end, for exact per-run diffs

Status: built and merged 2026-10-19 (PR #109; diffs series). Build-time amendments are recorded in this file. Depends on: T01 (store, `applyEvent`, 90-day thread prune), T03 (`run.started`/`run.ended` in `bridge/threads/journal-ingest.ts`), T26 (`scope=run` 501 stubs on `/api/files/git/review/patch` and `/review/contents`, the contents route in `shared/v2/review.ts`, shared numstat parser), the Sightr state dir. Plan: [`README.md`](README.md) "Diffs series". Bridge + shared only; the UI is T31.

## Problem

T24's card is built from the journal's `file_change` items, so it misses edits made through a shell (`sed -i`, `npm install`, a formatter, `git checkout`) and cannot say which edits were this run's when the tree was already dirty. `bridge/workdir-git.ts` has no per-run baseline: every diff is against HEAD or a base branch. T3 solves this with server-side checkpoints (`CheckpointCaptureService`, `CheckpointService`, `CheckpointStore`, `CheckpointDiffQuery`, projection `OrchestrationV2Checkpoint`, event `checkpoint.captured`, item `checkpoint`), writing hidden refs into the user's repo. This slice ports the idea as plain git plumbing against a **private object store owned by Sightr**: nothing is written into the user's `.git`. Rollback and restore are out; so is every UI.

## Change

### 1. When a snapshot is taken (`bridge/threads/checkpoints.ts`, new)

- A subscriber on `store.onCommitted` (a throw never rolls anything back). `run.started` queues the **start** snapshot, `run.ended` queues the **end** snapshot (`completed`, `failed` and `interrupted` alike). Run boundaries are the status transitions T03 already derives, so a run begun in the terminal gets its start snapshot exactly like a dispatched one; there is no dispatch hook. `bridge/threads/journal-ingest.ts` is not edited.
- Only for a thread whose harness is not `shell` (`SHELL_HARNESS`, `bridge/threads/capabilities.ts`) and whose pane cwd (`engine.current()`, the lookup `bridge/server.ts` gives `paneCwd`) resolves through `folderGit.openRepo(cwd)` to a worktree root inside `cfg.workRoot`. `openRepo` in `createFolderGit` (`bridge/workdir-git.ts`) is exported for this. The real root is stored on the checkpoint row; the end snapshot uses the stored root, not the pane (the pane may be gone).
- **Windows of validity.** A start snapshot is taken only within `START_WINDOW_MS = 30_000` of `run.startedAt`, an end snapshot only within `END_WINDOW_MS = 30_000` of `completedAt`. Outside it the side is `absent` (`start-missed` / `end-missed`), so a bridge restart never snapshots a tree that moved on. A start taken more than `APPROX_LAG_MS = 5_000` after `run.startedAt` sets `approximate`.
- **Start missed, or no start ref at the end:** no end snapshot is taken (an end alone proves nothing), and `checkpoint.captured` carries `status: "absent"` with the reason. The diff is never reconstructed from HEAD or the journal. T31 falls back to the journal when `status` is not `ready`.
- Absent reasons: `disabled`, `no-repo` (no `.git`, bare repo, outside the work root), `start-missed`, `end-missed`, `too-large`, `timeout`, `git-failed`, `sparse-checkout` (added after the safety re-review: a sparse index with a folder outside its cone on disk, or a sparse checkout whose index cannot be read as it is; section 2). Expiry is not an absent reason: an expired run stays `ready` with `live: false` (section 6).
- `shared: true` when another thread's run in the same repo root overlapped this one (their edits are in the diff; git cannot tell them apart). Both threads are snapshotted anyway.

### 2. The mechanism (`bridge/threads/checkpoint-git.ts`, new)

**Private store.** Per repo, one bare repo at `<stateDir>/checkpoints/<repoKey>.git` (`git init --bare` on first use, `gc.auto=0`). `repoKey` = sha256 (first 32 hex) of the realpath of the repo's git dir (`git rev-parse --absolute-git-dir`, run in the real repo and read-only), lower-cased on Windows and macOS only, whose file systems ignore case by default (amended after the safety re-review: lower-cased everywhere, two Linux repos differing only in case shared a store). Nothing is written into the user's `.git`: no objects, refs, index, config or reflog.

Every call goes through the hardened runner (`prefix` and `env()` in `bridge/workdir-git.ts`: hooks off, pager off, system/global config nulled, `GIT_OPTIONAL_LOCKS=0`) with `--no-optional-locks`. The runner gains an optional `timeoutMs` (default stays `GIT_TIMEOUT_MS`) and an `extraEnv`; `prefix`, `env`, `DIFF_FLAGS` and `parseNumstatRecord` are exported. Config the scrubbed env hides is read once from the real config (the `readEffectiveAutocrlf` pattern, generalised): `core.autocrlf`, `core.symlinks`, `core.excludesFile` (a global ignore list still applies), `core.attributesFile` (a global attributes file still decides line endings; added after the safety re-review) and passed as `-c`. Always passed: `-c core.longpaths=true -c core.safecrlf=false -c core.logAllRefUpdates=false -c commit.gpgsign=false`.

Per snapshot, `cwd` = repo root and `extraEnv` = `GIT_DIR=<private>`, `GIT_WORK_TREE=<repo root>`, `GIT_OBJECT_DIRECTORY=<private>/objects` (every write lands here), `GIT_ALTERNATE_OBJECT_DIRECTORIES=<real objects dir>` (`git rev-parse --git-path objects`; read-only reuse of unchanged blobs and trees; `;`-separated on Windows), `GIT_INDEX_FILE=<stateDir>/checkpoint-tmp/<uuid>.index` (absolute; deleted in `finally`, the dir is emptied at bridge start, before the first snapshot makes one). Real HEAD is resolved first with the real env (`git rev-parse --verify HEAD`, read) as a sha; unborn = none.

*Amended after the T30 safety review:*
- **No freshening.** The object-writing calls (`add -u`, `add`, `write-tree --missing-ok`, `mktree --missing`) run **without** `GIT_ALTERNATE_OBJECT_DIRECTORIES`: with it, git "freshens" (touches the mtime of) any object the real repo already holds instead of writing it. They write their own copy into the store. `commit-tree`, `diff`, `cat-file`, `ls-tree`, `rev-list`, gc and the `read-tree` fallback keep the alternate (reads). A write that fails on a missing object retries with the alternate. A sparse index stays sparse: the real `core.sparseCheckout`, `core.sparseCheckoutCone` and `index.sparse` are passed as `-c` and `info/sparse-checkout` is copied like `info/exclude` (expanding one rebuilds the cache tree, which writes and so freshens trees). Refused names inside a folder outside the cone (one sparse index entry) are cut from the finished tree with `ls-tree` + `mktree`. The user's `.git` is byte- **and mtime-**identical after a snapshot.
- **Private-call guard.** `stateDir` is made absolute at start. A private call needs an absolute `GIT_DIR` under `<stateDir>/checkpoints/`, `GIT_OBJECT_DIRECTORY` there too, `GIT_INDEX_FILE` (when set) under `checkpoint-tmp/`, and no `GIT_COMMON_DIR`/`GIT_SHALLOW_FILE`/`GIT_GRAFT_FILE`/`GIT_REPLACE_REF_BASE`. With a work root, a repo whose git dir, index, objects dir, exclude, sparse or attributes file lies outside it (a worktree `.git` file pointing elsewhere) is `no-repo`, as T26 and Files contain their roots.
- **Every step can fail into a record.** Store init, the ref check, the HEAD read and the exclude copy are inside the snapshot's `try`; a throw anywhere in the start or end handling records the side `absent: git-failed`.
- **8.3 aliases.** On Windows `isHiddenPath` (shared with T26) also refuses any segment shaped like a short name (`~<digit>`): a tracked entry named `ENV~1` would read `.env` through the file system.

*Amended after the T30 safety re-review* (this replaces the "No freshening" bullet's split by writer and its retry with the alternate, which the re-review measured: CRLF-committed files diffed whole-file, and a sparse index still freshened trees):
- **No call that reads the temp index sees the user's objects.** Reading an index can write trees: a sparse index expanded, or a full one collapsed under `index.sparse`, rebuilds its cache tree, and with the alternate present each tree the real repo holds is freshened (measured: a folder outside the cone on disk touched tree objects and a `.pack` on every reader, and made the end `git-failed`). So `ls-files`, `diff-files`, `update-index`, `add`, `write-tree` and `mktree` run with the private store alone, and nothing retries with the alternate. It stays only on calls that read objects by name and no index: `pack-objects`, `ls-tree`, `commit-tree`, `diff`, `cat-file`, `rev-list`, gc, and the `read-tree` fallback (a fresh full index, `index.sparse=false`).
- **The index blobs a rehash needs are copied in first.** git's safer-autocrlf check (`core.autocrlf=true|input`, `text=auto`) reads a file's index blob to decide whether a CRLF file is kept as it is; one it cannot read counts as "no CR", so without the alternate a CRLF-committed file came out LF, a whole-file diff (Git for Windows ships `autocrlf=true`, so this is the default case). Before git hashes a tracked file, its real index blob is copied into the store: `cat-file --batch-check` (store alone) names the missing ones, `pack-objects --window=0 --depth=0` reads them through the alternate and writes one pack into the store's `objects/pack` (the guard refuses any other destination and `--stdout`). Refused names are never copied. The index version of each file a run changes is therefore copied once per store.
- **Tracked files are rehashed by name, each against its real entry.** `add -u` is replaced by `update-index --add --remove -z --stdin` fed the `diff-files` list: `add -u` also rehashes every racy entry, whose blob may not be in the store (measured: a racy index at the start, then the operator's `git status`, listed an untouched CRLF file at 10/10). Before the refresh, the blobs of every path `diff-files` names are copied (when they fit under `MAX_TRACKED_CHANGES`), so the refresh judges files as the operator's git would. Each settle round lists again and copies again, and an entry an earlier round rewrote is put back to its real one first (`update-index --index-info`), so every rehash is against the real index entry, as `git add` would be. `update-index` stops at the first file it cannot read and writes nothing: that file keeps its entry and goes to `skipped_paths`, the rest go again (at most 32 times). Untracked files are added with `add --sparse`: a new file outside a sparse checkout's patterns is a file `git status` lists.
- **The index is read as the file holds it.** The seeded index is listed with `ls-files -z -s -t --sparse` (store alone, `sparse.expectFilesOutsideOfPatterns=true`), and the listing must have as many entries as the file's header: with the trees out of reach, git drops what an expansion cannot read and still exits 0. `index.sparse` is the repo's value if that matches, else the other one, and holds for the whole snapshot (a sparse index stays sparse, a full one full). For a sparse index `sparse.expectFilesOutsideOfPatterns=true` is passed on every call, a skip-worktree entry present on disk (a folder outside the cone git left for untracked or ignored files, or one an agent made) makes the side `absent: sparse-checkout` (git would have to expand the index to look inside it; checked before the first reader and again before the commit), and the finished tree must hold every sparse folder with the oid the index named. A full-index sparse checkout needs none of this: git clears the skip-worktree bit of a file put back on disk itself, without expanding anything. A sparse checkout whose index cannot be read as it is takes no `read-tree` fallback (HEAD's tree would read every file outside the cone as deleted): `absent: sparse-checkout`.
- **Attributes.** `info/attributes` (`--git-path info/attributes`, inside the work root like the others) is copied like `info/exclude`, and `core.attributesFile` is read and passed like `core.excludesFile` (measured: `*.txt -text` in `info/attributes` under `autocrlf=true` gave 1/0 for git's 3/2).
- **Guard.** A private call's env may not set any `GIT_CONFIG*` name (`GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`/`_KEY_n`/`_VALUE_n`, `GIT_CONFIG_GLOBAL`, ...), nor a `GIT_*` name in anything but upper case (Windows reads names without case).
*Amended after the verification of the re-review fixes* (CI on Linux, git 2.55, served a pruned run's files that Windows, git 2.52, answered `expired`; and four findings below):
- **A snapshot's trees are its own, on every git version.** With the store alone the user's cached trees are missing, and git decides by version what that means: 2.55 rebuilds and writes each missing tree, while 2.52 to 2.54 take a cache tree whose objects are missing as valid (`cache_tree_fully_valid` tests `odb_has_object` the wrong way round; fixed in 2.55) and write nothing, so an unchanged snapshot's trees stayed in the user's repo. Before each `write-tree` a root-level refused name (`.sightr-tree-reset`, never in a snapshot) is removed from the temp index, which invalidates the root; `update_one`, right in every version, then writes each folder whose tree is not in the store yet (once per store; later snapshots find them). A folder outside a sparse cone stays one entry naming the user's tree. So a snapshot holds its trees and both sides of every file its run changed; only the blobs of files it did not change (and folders outside a sparse cone) are read through the alternate, by gc alone.
- **Conflicted files go through `git add`.** With `core.filemode` or `core.symlinks` off, `git add` takes a conflicted file's mode from the conflict's entries (stage 2, else 1 or 3); `update-index` would take it from the file (measured: a 100755 file conflicting under `filemode=false` came out 100644, with an `old mode`/`new mode` patch). Paths with an entry at stage 1 to 3 are added with the literal `add --sparse --pathspec-from-file` call the untracked files use.
- **A path behind a symbolic link is a deletion.** `update-index` refuses a tracked path whose folder became a link ("is beyond a symbolic link") and stops; that path is removed with `update-index --force-remove`, as `add -u` records it, and the rest go again. The pass cap is gone: each pass drops at least one path, and the snapshot's budget bounds the time (more than 32 unreadable files no longer meant `git-failed`).
- **The repo's own config decides.** workdir-git's runner passes the machine's `core.autocrlf` as `-c`, and `config --get-regexp` lists such command-line values last, so the machine's value beat the repo's (measured both ways: 1/1 where `git diff` said 3/3, and 20/20 where it said 1/1). The real repo's config is read with `config --show-scope --get-regexp` and only its `local` and `worktree` lines are kept (the real-side guard allows exactly that call).
- **A refused folder inside a folder outside the cone is cut whole**, not kept as an empty tree whose name would sit in the store.

1. Seed: copy the file named by `git rev-parse --git-path index` (real env) to the temp path: a read of the real index file that keeps the stat cache, so only changed files are rehashed. If that fails or git cannot read it as it is (above), `git read-tree <HEAD sha>`; unborn, start empty.
2. Ignore rules: before the pre-flight, copy the real `info/exclude` (`--git-path info/exclude`; empty file if absent) to `<private>/info/exclude`, and `info/attributes` and `info/sparse-checkout` alike. The worktree's `.gitignore` files apply as usual and the global list via `-c`. Pre-flight: `git ls-files -z --others --exclude-standard`. Drop refused names (`isHiddenPath`: `.env`, keys; counted in `skipped`), symlinks, directories, files over `MAX_FILE_BYTES = 5 MiB`, then stop at the caps in section 3.
3. `git update-index --add --remove -z --stdin` fed the `diff-files` list (tracked edits and deletions; amended after the safety re-review, this read `git add -u`), then `git add --sparse --pathspec-from-file=- --pathspec-file-nul` fed the allowed untracked list. Ignored files are never added. A path git cannot read (locked by the running agent, long path) is named on stderr (`LC_ALL=C`): it goes to `skipped_paths`, is dropped from every file list, and the snapshot is still `ready`. Unparseable stderr: `git-failed`.
4. Settle: `git write-tree`, wait 250 ms, `diff-files` and `update-index` again, `write-tree` again. Equal: done. Different: retry up to 3 rounds (the agent is writing); after that keep the last tree and set `unsettled`.
5. `git commit-tree <tree> -m "sightr checkpoint <threadId> <ordinal> <side>"` with env `GIT_AUTHOR_NAME=GIT_COMMITTER_NAME=Sightr`, `..._EMAIL=sightr@localhost`, both dates the capture time. **No parent** (amended after the safety review; this read `[-p <HEAD sha>]`): no diff or route reads it, a parent made every gc in the store walk the user's whole history (1.6 s at 20k commits, against 0.16 s), and in a shallow clone gc failed outright on the cut-off parents (the store has no `shallow` file), so the sweep deleted refs without freeing anything and the size cap then expired every run. `commit-tree` runs no hooks and signs nothing.
6. `git update-ref refs/checkpoints/<threadId>/<ordinal>/<start|end> <commit>` in the private store. The id part must match `^[A-Za-z0-9_-]{1,64}$` (else a hash of it). An existing ref is reused, never moved, so a retry or replay is a no-op.

Windows: CRLF follows the effective `autocrlf`, so blobs match what the operator's `git status` sees; roots and git dirs are `realpath`s compared case-insensitively (8.3 names); a detached HEAD changes nothing (snapshots have no parent). **Verify at build:** that a linked worktree (own index and git dir, shared objects dir) and a submodule resolve their real git dir, index and objects dir correctly through the `--git-path` calls above.

### 3. Cost control

- Time: `SNAPSHOT_BUDGET_MS = 20_000` for the whole snapshot (per-command `timeoutMs` is the remainder). On expiry kill git, delete the temp index, `absent: timeout`.
- Caps: `MAX_UNTRACKED_FILES = 5_000`, `MAX_UNTRACKED_BYTES = 64 MiB`, `MAX_TRACKED_CHANGES = 20_000` (from `git diff-files -z --name-only`). A trip makes that side `absent: too-large` with `truncated: true`. A partial tree is never committed: a cut snapshot would read as mass deletions.
- Single-flight: one snapshot, patch capture or gc per private store at a time, a FIFO queue behind it; at most 2 repos at once. A run-scope review read waits with its deadline (25 s) enforced while it waits, and at most 32 such reads wait at once (T26's `REVIEW_QUEUE_MAX`); past either it answers `busy`. A large monorepo therefore costs one stat pass per snapshot (warm stat cache from the seeded index) and degrades to `absent`, never to a wrong diff. Subtree-scoped snapshots are a follow-up.

### 4. Diff query, stored patches and routes (`bridge/threads/checkpoint-diff.ts`, new)

- On `run.ended` capture, after both refs exist: `git diff --numstat -z --no-ext-diff --no-textconv --no-renames --no-color <startCommit> <endCommit> --` (commit shas, private env), parsed by `parseNumstatRecord`. A rename shows as a delete plus an add, as in T26. Files cut at `MAX_CHECKPOINT_FILES = 500` set `truncated`; totals still sum every record. Paths on the Files refusal list are counted in `hidden`, not listed.
- **Stored patches.** Then, per listed file (concurrency 2, `PATCH_BUDGET_MS = 20_000`): `git diff -U3 --no-ext-diff --no-textconv --no-renames <start> <end> -- :(literal,top)<file>` (whitespace on). Caps: `DIFF_CAP_BYTES` (256 KB) per file, cut at the last whole line and flagged `truncated`; `MAX_PATCH_BYTES_PER_RUN = 2 MiB`, past which (or past the budget) a file keeps no stored patch (`patch` NULL, `truncated`). Binary files store `patch ''`, `binary 1`. Written into `run_checkpoint_patches` in the same transaction as the end-phase files list. Refused names never entered a snapshot, so never a patch. Rows go with the run (FK cascade, so with T01's 90-day thread prune), and a global soft cap `MAX_PATCH_STORE_BYTES = 256 MiB` of `bytes` is pruned oldest-run-first by the sweep (patch rows only; the checkpoint row and file list stay).
- Because it compares two trees, files already dirty before the run and unchanged by it are absent, an edit reverted within the run is absent (empty net diff), and a commit the agent makes mid-run does not matter.
- "Authored paths" (T3 `CheckpointDiffQuery`; verify its exact rule at build): each file carries `authored: boolean`, true when its path appears in the run's `file_change` items. `authored=1` on the query hides the rest. Default is off, because shell-made edits are real changes.
- **Patch route:** T26's `GET /api/files/git/review/patch?scope=run&threadId=&runId=&file=<repo path>&w=<0|1>` replaces its 501 stub (the legacy `/api/files/git/diff` Git-tab route is unchanged). It needs no `path`: the checkpoint row names the repo, so archived threads work. Answer in T26's patch shape (`shared/v2/review.ts`; verify the type at build) or `{available:false, reason}`. The file list is never fetched: it is on `Run.checkpoint`. Refusal list, `cache-control: no-store`, ETag via `computeEtag` (`bridge/http-cache.ts`) with 304.
  - `w=0`: the stored row, no git call; ETag over `runId+file+bytes+truncated`. Works for archived and expired runs until the row is pruned.
  - `w=1`, and a `w=0` row with `patch` NULL: computed live from the private store (same argv, `-w` when asked; ETag over `startCommit+endCommit+file+w`), else `{available:false, reason:"expired"}`.
- **Contents:** T26's `GET /api/files/git/review/contents` gains `scope=run` (`threadId`, `runId`, `file`; `ReviewUnavailable` gains `"expired"`): old side `git cat-file blob <startCommit>:<file>`, new side `<endCommit>:<file>`, private env, T26's side states and 1 MB cap. Blobs are already line-ending normalised, so no CRLF folding. Live only; `expired` once objects are gone.
- **Liveness check.** Before every live diff or contents call run `git cat-file -e <commit>^{commit}` on both commits (private env). A failure, or a later `diff`/`cat-file` that exits non-zero on a missing object, marks the row (`objects_expired_at`, `checkpoint.expired` emitted) and answers `expired`.

### 5. Store and contracts

- **Migration 7** (`bridge/threads/store.ts`): `CREATE TABLE run_checkpoints (run_id TEXT PRIMARY KEY REFERENCES runs(id) ON DELETE CASCADE, thread_id TEXT NOT NULL REFERENCES threads(id) ON DELETE CASCADE, ordinal INTEGER NOT NULL, repo_root TEXT NOT NULL, status TEXT NOT NULL, reason TEXT, start_commit TEXT, start_at INTEGER, end_commit TEXT, end_at INTEGER, files_json TEXT, additions INTEGER, deletions INTEGER, hidden INTEGER, skipped INTEGER, truncated INTEGER, approximate INTEGER, shared INTEGER, unsettled INTEGER, objects_expired_at INTEGER)` plus `run_checkpoints_thread (thread_id, ordinal)`; `CREATE TABLE run_checkpoint_patches (run_id TEXT NOT NULL REFERENCES runs(id) ON DELETE CASCADE, path TEXT NOT NULL, patch TEXT, binary INTEGER NOT NULL, truncated INTEGER NOT NULL, bytes INTEGER NOT NULL, PRIMARY KEY (run_id, path))`; and `ALTER TABLE projects ADD COLUMN checkpoints INTEGER` (NULL = default on, 0 off, 1 on).
- **`shared/v2/contracts.ts`** (additive; T3 names, times epoch ms): `RunCheckpoint` (mirror of `OrchestrationV2Checkpoint`; verify field names at build) `{ runId, threadId, appRunOrdinal, status: "pending" | "ready" | "absent", reason?, live?, files: CheckpointFile[], additions, deletions, capturedAt?, truncated?, hidden?, skipped?, approximate?, shared?, unsettled? }`, where `live` = private-store objects still present (false once the sweep deletes the refs or a liveness check fails); `CheckpointFile { path, kind: "added" | "modified" | "deleted", additions, deletions, binary?, authored? }`; `Run.checkpoint?: RunCheckpoint` (filled by `snapshotThread`, not stored on `runs`); events `checkpoint.captured: { checkpoint: RunCheckpoint; phase: "start" | "end" }` and `checkpoint.expired: { runId }` (emitted by the sweep and the liveness check, so clients flip `live` without a refetch); turn item `checkpoint { checkpointId, files: CheckpointFile[], checkpoint: RunCheckpoint }` (T3's item type and field names; `checkpointId` is the run id, T3's `scopeId` has no counterpart; renamed from `checkpoint_summary`, which in T3 is a handoff strategy), id `checkpoint:<runId>`, upserted by `applyEvent` on the end phase; web2 draws no timeline row for it until T31; `Project.checkpoints?: boolean`; command `project.checkpoints.set { projectId, enabled }` (`decide.ts`, beside `project.rename`).
- The server form of the event (`bridge/threads/events.ts`) also carries `repoRoot`, `startCommit`, `endCommit`, `skippedPaths`; `toWireEvent` strips them. No absolute path (the private store included) or sha reaches a client.
- **Replay and idempotence.** The start phase writes a `pending` row, the end phase upserts the same `run_id` row; `checkpoint.expired` sets `objects_expired_at`. Replaying all events from empty reaches the same `run_checkpoints` table; patch rows are a side table written beside the end event, not event-sourced, so a replay drops them (live fallback, else `expired`). A duplicate `checkpoint.captured` for a finished phase changes nothing. After a crash between snapshot and event, the retry finds the existing ref (step 6) and appends the event once.
- An unknown item type or event must not break web2: verify at build that `web2/src/stream/*` ignores them; add a no-op only if it does not (the one permitted web2 edit).

### 6. Retention and GC

- Objects live for the retention window. Defaults: keep the newest `CHECKPOINT_KEEP_RUNS = 50` runs per thread and `CHECKPOINT_KEEP_DAYS = 14`; an archived thread's refs go 24 h after `thread.archived`; `thread.deleted` or the 90-day prune (T01) deletes them at the next sweep. Past `256 MiB` per private store (measured on the store's `objects/` files, not summed from rows; `count-objects -v` reports loose objects as 0 KiB on git for Windows), the oldest runs go first, and only while gc frees what is dropped. A `pending` row whose run has not ended after `PENDING_MAX_MS = 24 h` is expired too (its end will never come); if its `run.ended` does come later, the end is `absent: start-missed` and no end snapshot is taken (amended after the safety re-review: an end was snapshotted against the dropped start).
- Sweep at bridge start (after 30 s) and hourly, per store: `git for-each-ref --format=%(refname) refs/checkpoints/`, then `git update-ref --stdin` with one `delete` per ref that is expired, or whose thread or run is not in the store (orphans). If any went: set `objects_expired_at`, emit `checkpoint.expired { runId }` per run (`status` stays `ready`; the stored list and patches keep showing), then `git gc --prune=now` in the **private store** (`GC_TIMEOUT_MS = 120_000`). Sightr owns this store, so pruning is safe here; it is never run in the user's repo. `gc` repacks local objects only (`-l`), so real-repo objects are untouched. A failed gc is followed by `rev-list --objects --missing=print` on each live run's commits: runs whose objects are gone (a rewrite plus prune in the real repo) are expired and their refs dropped, then gc runs once more; if it still fails it is retried next sweep. With no ref gone, a store past its byte cap, or holding more than `MAX_STORE_PACKS = 16` packs (a snapshot that copies index blobs writes one), is gc'd first, so objects no run reaches (an earlier settle round's trees, an expired run's blobs) never push live runs out (amended after the verification). Then prune patch rows past `MAX_PATCH_STORE_BYTES`.
- **Orphan sweep:** a private store with no `run_checkpoints` row, or whose `repo_root` no longer exists, is removed (rows of the latter get `objects_expired_at` and the event). Expect per snapshot about the compressed size of files changed since the last one (typically 10 to 200 KB, a few trees, a 200 B commit); unchanged blobs are read from the real repo, not copied; the index version of each file a run changes is copied once per store (so git's CRLF check can read it), and the first snapshot in a store writes every folder's tree once (section 2).
- **Alternates failure mode.** The private store depends on the real repo's objects for the blobs of files a run did not change (and for folders outside a sparse cone). If the user rewrites history and prunes (`gc --prune=now`, `filter-repo`), those can vanish. A run's own files keep serving (its trees and both sides of what it changed are in the store; amended after the verification: this read that the run fails `cat-file`/`diff` at once, which held only on git 2.52 to 2.54 and only for an unchanged snapshot). The next gc in the store cannot walk the run and fails; `rev-list --objects --missing=print` finds the run, which is then expired (event, `live: false`), its refs dropped, and gc runs again; stored patches still serve. The section 4 liveness check still answers `expired` for a store that lost its own objects. Copying all reachable blobs instead would remove the dependency at the cost of the private store's size.
- Visible side effects: none in the user's repo (`git log --all`, `git for-each-ref`, `git push --mirror` see nothing new). The only footprint is `<stateDir>/checkpoints/` and the SQLite rows.

### 7. Consent and opt-out

Nothing is written into the user's repo, so **default: on**. Off switches: `SIGHTR_CHECKPOINTS=0` (read in `bridge/index.ts` like `SIGHTR_V2`, kills the subscriber and the sweep) and `project.checkpoints.set` (stored per project, effective value on `Project.checkpoints`). Either yields `absent: disabled`. Turning a switch off does not delete existing checkpoints; the retention sweep still removes them (disable-then-clean).

Not in this slice: any UI (T31), rollback or restore, worktree creation, a pre-send snapshot in the dispatcher, subtree-scoped snapshots, and anything written into the user's repo. Scope `branch` elsewhere stays committed-only (T26).

## Invariants

- The user's `.git` directory and working tree are byte-identical before and after any snapshot, sweep, liveness check or failure. The only writes are under `<stateDir>/checkpoints/` (and `checkpoint-tmp/`) and the SQLite store.
- A refused name never enters a snapshot or a stored patch.
- A `ready` checkpoint is a diff between two complete trees; any cap, timeout or missing side makes it `absent`, never a guess. Expiry removes only the live view, never the stored list or patches.
- A ref, once written, is never moved. No absolute path or commit sha is on the wire.

## Tests

Fixture repos are built in a temp dir with the real `git` (no network); `bridge/threads/checkpoint-git.test.ts`, `checkpoint-diff.test.ts`, `checkpoints.test.ts`, plus store, route and contracts additions beside their sources.

- **Fixtures:** clean tree; dirty tree before the run (stays out of the diff); untracked; ignored (by `.gitignore`, the real `info/exclude` copied across, global list); deleted; rename (delete plus add); binary (`binary: true`, 0/0); edit then revert (no file listed); concurrent commit by the agent mid-run (diff unchanged); no repo, bare repo, cwd outside the work root (`absent`); detached HEAD; repo with no commits; linked worktree and submodule (real git dir resolved); CRLF file under `autocrlf=true`; after the safety re-review: a CRLF-committed file under `autocrlf=true` and under `text=auto`, files older than the index and a racy index, an edit is 1/1 with the blob the operator's `git add` makes; `info/attributes` and `core.attributesFile`; a file rewritten between settle rounds; a sparse index with a folder outside the cone on disk (`absent: sparse-checkout`, the user's `.git` mtime-identical), a new folder outside the cone, a full index in an `index.sparse` repo; a file another process holds locked (Windows); after the verification: a conflicted executable under `filemode=false` and a conflicted link under `symlinks=false` (the mode `git add` gives), the repo's `core.autocrlf` against the machine's both ways, a tracked folder replaced by a link (a deletion) and more than 32 unreadable files (still ready), a refused folder inside a folder outside the cone (cut whole), an unchanged snapshot's trees in the store, a pruned run serving its files until the sweep's gc expires it, a store that lost its own objects (`expired`), a store over its cap only through unreachable objects (gc first, no run goes), more than 16 packs (gc'd into one).
- **Untouched proof:** hash the whole `.git` tree (every file, including `index`, `logs`, `objects`, `refs`, `config`) and every working file before and after a snapshot, a failing snapshot, a timeout, a sweep and a live diff; equal. `git status --porcelain` identical; no `index.lock`; the private store holds the new objects and refs.
- **Safety:** a `.env` file is not in the end tree; a hook that writes a marker file never runs; `commit.gpgsign=true` in repo config does not prompt.
- **Caps and cost:** untracked file count, bytes and single-file size each yield `absent: too-large` or a skip as specified; an injected runner that exceeds the budget gives `timeout` and removes the temp index; two snapshots on one store never overlap, two repos run in parallel; a file rewritten during settle gives `unsettled`.
- **Run flow:** `run.started` then `run.ended` yields one start and one end ref, one `checkpoint.captured` per phase and one `checkpoint` item; a run begun with no dispatch behaves the same; missed start gives `absent: start-missed` and no end ref; both windows; re-delivery adds no row and moves no ref.
- **Store:** migration 7 from a version-6 file; replay from empty equals the live `run_checkpoints` projection; `snapshotThread` fills `Run.checkpoint`; server fields absent from the wire form; deleting a run cascades its patch rows.
- **Stored patches:** per-file cap cuts and flags `truncated`; the 2 MiB per-run cap leaves later files with NULL patch (live fallback while objects exist); the global cap prunes oldest-run-first and keeps the file lists; a refused name has no row.
- **Route:** `scope=run` with no `path`; `w=0` served from SQLite with no git call (counting runner) for an **archived thread**; `w=1` and contents computed live; ETag 304; a refused path; `w=1` after expiry answers `{available:false, reason:"expired"}` while `w=0` still serves.
- **Retention:** 51st run, 15-day-old run, archived thread, deleted thread, orphan ref and the 256 MiB cap each delete exactly the right refs and emit `checkpoint.expired`; **private-store gc after ref deletion shrinks the store directory**; an orphan store (repo root gone) is removed; the user's `.git` hash is unchanged throughout.
- **Alternates breakage:** rewrite the fixture's history and prune the real repo (`reflog expire`, `gc --prune=now`); a live diff then fails the liveness check, the run becomes expired (`live: false`, event emitted), and its stored patches still serve.
- **Switches:** `SIGHTR_CHECKPOINTS=0` and project off each yield `disabled` and write no ref.

## Open questions

- Is `MAX_PATCH_STORE_BYTES = 256 MiB` right? Patches are text and compress poorly in SQLite rows; measure on a month of real runs.
- `GIT_ALTERNATE_OBJECT_DIRECTORIES` with Windows long paths (and `;` separation): does git honour `core.longpaths` for alternates? Verify at build; fall back to a short `objects/info/alternates` file if not.
- Linked worktrees and submodules each get their own private store (own git dir), sharing real objects via alternates: confirm at build that this is correct and cheap, or key by the common dir.
- Two threads running in one repo see each other's edits (`shared` only flags it): acceptable until worktrees (decided: snapshot anyway).
